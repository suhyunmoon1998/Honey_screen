# Honey Case Adventure — Codex 실행 안내

이 폴더는 단순한 “긴 프롬프트”가 아니라, Codex가 실제 제품을 일관되게 구현하도록 만드는 엔지니어링 계약서입니다.

## 권장 실행 순서

1. 새 Git 저장소를 만들거나 기존 저장소 루트에 이 팩의 파일을 복사합니다.
2. `assets/honey-source.png`를 실제 앱의 `apps/web/public/brand/honey.png`로 복사합니다.
3. Codex에서 저장소를 엽니다.
4. GPT-5.6 Sol의 높은 reasoning 설정과 Plan mode를 사용합니다.
5. `codex-tasks/00-plan-and-rfc.md`를 먼저 실행합니다.
6. Codex가 만든 RFC, ADR, 실행 계획을 검토합니다.
7. 이후 `01`부터 `05`까지 한 단계씩 실행합니다.
8. 각 단계가 끝날 때마다 테스트 결과와 Git diff를 확인한 뒤 다음 단계로 진행합니다.

## 중요한 제품 결정

- 첫 버전은 마이크로서비스가 아닌 **모듈형 모놀리스 + 백그라운드 워커**입니다.
- 클라이언트가 하루에 접하는 서로 다른 실질 질문은 현지 날짜 기준 최대 10개입니다.
- Honey의 성장은 법적 사건의 강도나 승소 가능성과 완전히 분리합니다.
- PWA 설치 이벤트는 브라우저마다 신뢰도가 다르므로, “설치 완료”만을 핵심 운영 이벤트로 삼지 않습니다.
- 운영팀 알림의 신뢰 가능한 기준은 가입 완료, 첫 미션 시작, 푸시 구독 활성화, standalone 모드 첫 실행입니다.
- 서비스 워커는 인증된 HTML, API 응답, 답변, 문서 등 민감 데이터를 캐시하지 않습니다.
- 법률 질문과 문구는 코드가 아니라 버전 관리되는 콘텐츠로 취급하며 변호사 승인 상태를 둡니다.

## 현재 Honey 이미지

제공된 이미지는 203×245 PNG입니다. 초기 MVP에서는 140–180 CSS px 정도의 프레임 안에서 사용하고, 전체 화면 배경으로 확대하지 마세요. 프로덕션 출시 전에는 동일 캐릭터의 고해상도 원본과 앱 아이콘용 정사각형 자산을 준비하는 것이 좋습니다.
